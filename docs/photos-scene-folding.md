## Reachable flow

Open the main **Photos** root in square or natural photo layout. The native stack-icon menu above the timeline exposes **Scene grouping**, current evidence status and **Reload scene evidence**. The default for the current browsing context is enabled. It is not an account-independent persisted preference. Once an eligible complete loaded month has been verified, covers show their actual scene member count. Tap a collapsed cover or its badge to expand; the badge collapses an expanded group. Long-press preview and a normal expanded photo still refer to one original asset. No scene editing, regrouping, rescan or write controls are invented.

The control does not query albums, Library collections, videos, memories, scoped day/week/month routes, inactive tabs, a covered Viewer, selection mode, opening prefixes or coarse date-card layouts. Turning it off restores the original projection immediately. Unsupported, unavailable and failed queries show distinct text; all discard accepted hiding evidence and show the originals until explicit Reload or a source-context change.

## Original indexes, dates and scrolling

`TimelineSemanticCatalog` and canonical Index are unchanged. Only fine-grid item frames/visible items are projected; every rendered item retains its original asset ID, original `nodeIndex` and original `assetRange`. Date headers still describe the original capture-day membership. A child shown under another day's cover has its own actual capture-date annotation; the summary is never assigned its cover's date. Coarse day/week/month/year projections remain unchanged.

Because expanded children can have nonmonotonic original indexes, a fine-grid materialized window touching an evidence month expands to that complete month range. It cannot slice an expanded group in half at the ordinary raw-index window boundary. This can exceed the usual1080 metadata-item window for a large verified month; UIKit still creates viewport cells lazily. No performance benchmark or large-library device claim is made.

The actual UIKit controller captures the cover's viewport Y before a toggle and reinstalls the projection anchored to that same original asset. Dates/return focus targeting a folded member map to its cover without changing the target's original catalog index. Returning from a Viewer that visited an original folded child first expands that child's group so the original photo can be a real return target. Viewer neighbors are still the original catalog's existing reversed ±80 neighborhood, including originals that are currently folded.

Selection mode disables scene projection and returns all original items. It never interprets a cover tap as a multi-photo mutation. The optional `assetSelectionActive` input is an explicit seam for an existing/future selection owner; this slice does not add a new bulk-selection UI or alter current single-photo management flows. iPad layout, keyboard, split-view and resize work are excluded.
