## Actual contract

Current source is bound to parent server `1511d3c457c19221fc51c8d3a17a87b46b18f57b`; Scene controller/DTO/service/Web manager are unchanged from the earlier `301d510` inspection. No upstream sync or server change occurred; Remmich upstream remains `672f02e`.

- `POST /api/fork/scene-stacks/query`, normal authenticated `asset.read`, body exactly `{ "ids": ["asset UUID", ...] }`, at most5000 IDs per call. No owner/path/scan settings are accepted.
- Successful status is **201**, not smart search's200: controller has `@Post` and no `@HttpCode`; installed Nest `router-response-controller.js:getStatusByMethod` returns CREATED for POST. Real scene HTTP is not run in this slice.
- Response `{ "available": true|false, "groups": [{ "id": "opaque key", "coverId": "asset UUID", "members": ["asset UUID", ...] }] }`. Group ID is a nonempty case-sensitive opaque display key, never forced into UUID syntax or used as an API path. Covers/members are actual asset UUIDs. Current manifest implementation uses UUID group IDs, but the client does not impose that on the wire interface.
- `available=false` means evidence unavailable, not “no photos.” Empty IDs short-circuit on the server before checking a manifest and can report available=true merely because a directory is configured; this client never uses empty IDs as a readiness probe and sends no query for an empty photo month.
- The controller is excluded from official OpenAPI. The raw schema remains unchanged. SDK uses a narrowly named hand-written read-only operation through existing authentication and foreground transport, matching exact operationID/method/path. It does not weaken the general write policy or put POST into the persistent GET journal.

Server evidence: `server/src/controllers/scene-stack.controller.ts:9–21`, `dtos/scene-stack.dto.ts:4–17`, `services/scene-stack.service.ts:38–87`, `web/src/lib/queries/scene-stack.query.ts:10–28`, `web/src/lib/managers/timeline-manager/scene-stacks.ts`. Server returns only groups whose complete members are in that request and still owned IMAGE/timeline/non-trash/non-offline with matching updatedAt/native stackId. Any member becoming invalid unfolds the whole group. Groups do not overlap. Web retains the original bucket DTO and changes only its display projection.

## Page behavior and safety boundaries

1. Original repository creates a generation-bound `SceneStackReading` facade. It reads fresh standard owner-only timeline months and whole bucket GETs, bypassing durable completed GETs. The pinned official schema lacks the Fork Web's `assetType` query parameter, so complete standard buckets are decoded before IMAGE filtering. Month counts can include videos; the page labels only the actual loaded IMAGE count and may show an empty-photo month.
2. Source snapshot retains all eligible original visible photo summaries, capture dates and official stack fields. As in Web, `withStacked=true` returns native stack representatives and single photos; native stack hidden children are not independently fetched or unfolded here. “All loaded photos” refers to this complete native visible-unit snapshot, including all scene-folded members, not a claim to load every hidden native-stack original. The scene request is split at5000 IDs as in Web. A group spanning chunks remains unfolded; the client does not invent half a group or extra requests to guess a group.
3. Every chunk reply must contain complete unique members, cover among members, IDs inside that exact chunk, unique nonempty group keys and no member overlap. A second whole-month validation rejects duplicate/overlapping groups across chunks. Store validates before publication again. Any bad group invalidates the entire round.
4. All chunks must succeed before any grouping projection is published. A later HTTP failure throws; unsupported404/405/501 returns an explicit unsupported state; available=false returns an explicit unavailable state. Earlier successful chunk groups are discarded in all three cases. Other HTTP failures, badJSON and wrong success statuses remain visible failures. Full photos remain on screen; an error is never labeled “0 scene groups.”
5. Collapsed covers show the real member count. Expand puts existing members immediately after the cover in their original bucket order, retaining each summary's real date and official stack. Turning grouping off immediately restores the original complete order. No index/state mutation or scene write API exists.
6. Native viewer freezes the **whole original month**, including folded members. Later page expansion/refresh does not change that viewer scope. Existing management revision synchronously retires the Store request and unfolds the page before the fresh-reader factory or reload completes, so an old held reply cannot hide a changed photo in that gap. Account/endpoint changes clear source, groups, expansion and viewer selection and cancel page tasks. Every facade method checks the original repository generation before/after asynchronous work; old facades cannot operate as credential clones.
