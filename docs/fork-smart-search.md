# Advanced smart search contract

Status: implemented on a draft client branch, awaiting its own macOS CI. The owning server's independent implementation is local and has not been deployed. This is not device acceptance or completion of the search stage.

Search retains Remmich's native controls, thumbnails, result snapshot and viewer. Ordinary smart queries use official legacy page numbers. Smart queries combined with EXIF comparisons, orientation, album membership or rating0 require `POST /api/fork/search/smart`; metadata searches keep their existing cursor route. No unsupported condition is removed to make a request succeed.

Reference-photo follow-up: long-press a real search result and choose **Find similar photos**. The active reference card offers **Use text search**; entering text or choosing a metadata mode also clears the reference and retains every filter. Selecting a result shows its known thumbnail version; a restored reference preset shows an icon without guessing a thumbnail revision or making an extra detail request. Existing viewer, download, share and management actions are unchanged.

Reference queries always use the Fork route, including reference-only searches. The body contains exactly one of trimmed `query` or `queryAssetId`, never an empty/null query beside the reference. References must be UUID v4 with the RFC variant, and cannot use metadata mode or legacy/page/metadata continuation types. Saved conditions retain the reference ID and full filters; malformed or mixed-source presets reject atomically. The server checks access to the reference asset; permission denial and missing embeddings stay403/400 errors rather than silently falling back. New synthetic wire, cancellation, preset and native source/pagination tests await Swift CI; no real-device or true similarity acceptance has been performed for this follow-up.

The authenticated read requires `asset.read` and rejects shared-link identities. It sends trimmed query text, a full structured filter, size(default60), withExif:true and an optional opaque cursor. Filters preserve people, calendar dates, country/state/city, make/model/lens, media, favorite/archive, rating absent/null/0–5, EXIF units, orientation and album status. Normal reads explicitly exclude trash and hidden/locked content; this client does not expose a locked search override.

The response keeps official SearchResponseDto/AssetResponseDto models. Its nextPage must be null; nextCursor is a Fork token or null at the end. Metadata tokens, legacy smart page numbers and Fork tokens have distinct native/SDK enum cases. Loaded item count is not a global match total. Changing query, filters, size, identity or server model requires a fresh search; the server binds its continuation to the request. Pagination does not promise a frozen library snapshot during concurrent changes.

Only404/405/501 on advanced smart become “this server does not support advanced smart search.” The error belongs to the current query/account generation, with selected conditions retained. Retry makes a new explicit read; availability is not durably cached across accounts.401/403,400,429, network and malformed responses retain their respective semantics. Failed pages retain existing results and the original retry position. There is no automatic fallback or mutation replay.

The exact operation identity, POST method, path and body are checked at the read boundary. Search POST never enters the durable GET queue. The default foreground session is ephemeral, has no cookies/cache, rejects redirects, and propagates cancellation. Clients without a durable queue use that same restricted session for Fork search. Response collection is bounded to32MiB. Supplied transport implementations are dependency injection for the existing queue and synthetic tests.

The wrapper reuses authentication middleware and generated filter/response Codable models, with the application's locked date transcoder. It does not modify generated Swift, the OpenAPI snapshot or ordinary SDK transport. The pinned [URLSession transport source](https://github.com/apple/swift-openapi-urlsession/blob/08796d36c99ad2318929bfa1d1e40f82194b65cc/Sources/OpenAPIURLSession/URLSessionTransport.swift#L191) constructs URLs by appending the relative request path to the verified API base, preserving subpath installs.

New synthetic tests cover complete two-page request bytes and media mapping, nullable rating states, individual advanced conditions, distinct continuation kinds, exact read-policy paths, missing/permission/condition/server statuses without fallback, malformed/repeated tokens, cancellation with a deliberately late response and complete preset reuse. Previous invalid-score and duplicate-slot checks remain; valid zero-rating smart search now has a positive Fork path. Local SwiftFormat and diff checks passed; package/app compilation, execution, UI screenshots and device behavior remain unverified for this follow-up.

Server evidence is separate:131 focused DTO/service/controller/filter tests and21 HTTP/isolated PostgreSQL cases passed for the local implementation, including vector/Chinese/EXIF/directory paths and permissions. Authentication and ML are synthetic fixtures; full server TypeScript checks remain affected by the existing dependency environment. No production photos, migrations or deployment were used.
