# 备份接续与大图库响应

2026-11-26：从可取得的最新候选 `0d5b4d4` 继续，未取得 Mac 本地 `d2d94bed` 的页面重做和接续实现。本分支独立实现同步前置核查，不把旧 Mac 安装包或旧 CI 作为验收结果。

## 行为

- 相簿枚举、资源描述与去重排序离开 UI 主线程；每项枚举检查取消，运行状态先发布。任务列表分页展示，恢复摘要只在队列更新时计算。
- 先导入官方 Immich SQLite。Importer 只读固定标识、缓存 checksum 和修改时间，要求当前账号一致；保留缺失项，不修改导出文件。当前支持 NAS 已有精简导出的四字段本机表与账号表。
- 手动继续、前台自动和系统后台都在唯一 Coordinator 与管理通道内完成整批核查，再把完整源版本许可交给 Worker。Worker 在原片导出之前拒绝许可外的任何源。
- 同手机优先按本机 ID 索引读取历史；找不到时才有限批量读取公开 Photos 元数据和完整 iCloud ID。历史 checksum 走官方 `bulk-upload-check`，每批最多 64 项；缓存摘要与实际读取字节证明是两种类型。
- 已核对官方iOS `PHAssetExtensions.swift`：`updatedAt`来自 `Int64(modificationDate.timeIntervalSince1970)`，只有整秒精度。缓存查询按同样精度选择候选，不能把同秒命中当作当前原片逐字节证明，因此已有项目只暂停、不生成成功回执。
- 历史版本不一致、缺摘要、歧义、服务器未命中或回收站项目保持待核查；不为补哈希下载原片。已有主体暂停并保留记录，不伪造完整 Live Photo、RAW+JPEG 或上传成功回执。
- Live Photo/RAW+JPEG只有主体命中时进入待核查。跳过与待核查都计入处理进度，但不计入新上传完成数。已尝试的新源只通过明确单项核查或已授权且验证过的网络恢复重新核查，仍须满足导入之后的时间/版本及完整远端元数据条件。
- 新拍摄和修改时间都晚于导入时刻、没有历史关联且官方完整同步元数据没有当前关联的源，才可获得新上传许可。查询失败、增量检查点、部分流或账号/端点变化都停止，不使用部分许可。
- 导入前新增但不在历史里的照片需要单独核查。未完成全量元数据读取时不把未知当作新照片。无记录时先停止，不自动将全库重新上传。
- 已安装Mac候选的 `existing` 与 `historyNeedsReview` 队列值保留读取兼容；不会把已有候选当作完整上传回执，不清空旧队列。未知未来格式仍拒绝。接续导入只使用本版明确导入的数据；原精简SQLite可以重复选择，原文件保持不变。
