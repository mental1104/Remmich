# 前台自动备份第一片

来源：`codex/feature-foreground-photo-backup`，固定基线 `59e9102a4b7a5b598aecc6fd763323dab5907fe2`。本片是独立、未整合的客户端源码；没有推送、触发 CI、合入 dev、修改父仓库 gitlink 或生产环境。它不包含另一条共享 Scheme 修复分支。

## 用户可见行为

- “前台自动备份（本账户）”默认关闭，按当前认证账号 namespace 保存在现有 SQLite 备份日志头中。首次选择相簿后，须先明确扫描保存，才能开启。关闭会等待原任务退役并保存关闭；开关写入失败有可见提示，本进程保持停止。
- 开启明确同意使用最近保存的包含相簿、排除相簿和 iCloud 原片选项。未保存草稿不参与自动计划；修改草稿会取消当前周期，必须重新扫描保存。已保存 `allowCloud=true` 仍表示用户允许下载 iCloud 原片；不会替用户强制改成 false 或默许 true。
- 仅在 App 活跃、当前已认证端点可用、已有 Photos 授权时扫描和上传。自动入口只查询授权，不调用会弹授权框的相簿列表读取器。锁屏、进入后台、账号/端点退役都取消原周期。
- 复用现有 `LocalPhotoChangeMonitor`；前台停留期间的新截图等变化合并为一个待处理扫描。重复生命周期/照片事件不创建并发上传器。关闭备份页面保留已明确开启的自动化；手动上传仍随页面关闭取消。
- 明确点击“停止并关闭前台自动备份”会取消、等待实际 Worker 清理，再保存关闭。单项用户取消、失败或未知的已尝试任务不会被照片变化重新激活。

## 队列与恢复边界

自动计划严格重新读取已保存的包含/排除集合，缺失相簿、权限或不一致结果报错并停止，不把失效的排除相簿当作空集合扩大范围。新计划复用 `PhotoBackupRunCoordinator`、`PhotoBackupWorker` 和实际 `LibraryMutationClient`，没有第二套上传、重试或任务服务。

只新增未出现过的完整源版本，或排队完全未尝试且没有失败/回执的已有项。同版本完成历史保留完成，不重新上传；失败、取消和已尝试暂停的 localID 整体阻断自动重试，部分 Live Photo/RAW+JPEG 回执原样保留。后台取消保留开关，但已经开始的未知项仍需手动检查并明确继续；本片不宣称自动恢复网络失败或中断中的任务。自动周期出现失败/未知回执会保存关闭自动规则，后续照片事件不重试。

账号、端点、权限和取消在 await 前后复查；换号旧周期只能保留旧账号的未知状态，不能发布旧成功或改新账号设置。配置和任务事实保存在既有账号 SQLite 中，日志头仅增加可选 Bool；旧日志缺失字段保持关闭，旧兼容读取器忽略并重写字段也只会丢失自动启用。没有 API、SQL 表结构或格式版本迁移；RAW+JPEG 仍保留格式 3 及双原图读取要求。

`PhotoBackupAutomaticTests` 包含 17 个函数 / 20 个声明场景，真实经过 Controller、Coordinator、Worker、SQLite 和上传 HTTP 客户端。仅系统授权/源快照/合成磁盘资源及 HTTP 回执为隔离替身；SHA1 从实际文件计算，官方查重 nonce 必须匹配，最终 GET 通过后才允许生产 Worker 保存完成。覆盖默认关闭/权限拒绝、失效排除、保存 iCloud 同意、明确开启、事件合并/新截图、未保存草稿和 await 中草稿变化、账号/权限退役、手动停止持久关闭、后台不重试已尝试项、未确认 HTTP 回执停止，以及 Live Photo 部分回执和手动重排未知历史的领域保护。交叉审查发现的旧 epoch 消费新 pending 问题在等待退役后先查 Task/epoch 修复，并用真实手动 Worker 导出门、多次条件退役和新周期实际成功回归。取消顺序由真正导出 await/Task 取消通知建立，失败/超时释放所有门并等待任务退役，没有 sleep 猜时序，也没有改产品存储架构制造检查点。

Swift 6 类型检查、这些运行断言、真实 Photos 变更通知、相簿 limited 权限变化、真实 iCloud 下载/取消、Live Photo/RAW+JPEG 自动周期和 iPhone/iPad 前台切换仍未验证；静态检查不能替代它们。运行时先验证上述新增测试，再做有限照片集验收，记录编译提交和设备 OS。OS 后台调度、后台上传、持久断网自动恢复/重试仍是后续独立工作，不能把本片称为后台自动备份。

回退时先在兼容客户端明确关闭自动备份并确认任务停止，再回退本片源码；保留既有 SQLite、部分回执和账号恢复资料，不删除远端资产或原片。原格式 3 的双原图读取要求仍然适用。
